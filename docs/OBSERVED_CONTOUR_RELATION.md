# Observed contour relation v1

`DUAL_REVIEW` / `PUBLIC_REPOSITORY_ONLY`. This developmental pure source component preserves positive sampled contour ownership among observed oracle REGION units. It supplies no causal truth qualification, same-face identity, physical whole-object occlusion, forecast or gate result. PR67's lifecycle serialization is unchanged.

`initialize` requires accepted lifecycle index zero and starts with no pairs or completed evidence. `advance` takes the accepted predecessor and current lifecycle, an opaque same-episode key, the prior separate relation reference, a narrow endpoint provider and decision cutoff. Exact typed permissions are only `ORIENTED_BOUNDARY_OWNERSHIP` and `OCCLUSION_ANNOTATION`, separate from lifecycle permissions. Denied permissions, future access, nonconsecutive lifecycle index, changed shape or episode mismatch are checked before provider access. Before fetching, the prior reference must bind the exact predecessor digest, and the current lifecycle must continue its command prefix, inventory, previous masks, first-seen and last-seen history. New nodes must first appear at the current index. The caller supplies accepted states; these checks do not qualify the adapter or prove episode identity from masks. A rejected update retains the exact prior reference and emits an unresolved reason; it cannot silently skip the missing relation observation. Provider failures propagate without mutation and require caller retention; no automatic retry authority is supplied.

The trusted `EndpointEvidence` payload is completed `t-1 -> t` endpoint1 only: existing `OrientedBoundaryElement` records, endpoint1-only `OcclusionRelation` records, matched availability, one of the two existing rules, and an explicit exact-current-raster/association assertion. Endpoint0 records, whole transition objects, transport, geometry, raw IDs and hidden inventory are denied. Binding records identify the accepted lifecycle digest/index/shape, opaque episode key and `ORACLE_REGION_UNIT`. The trusted adapter must establish same episode/unit and exact raster/association binding; typed validation and assertion flags are not physical qualification. No such actual adapter is implemented.

Directed positives are deduplicated owner-to-other-side pairs from endpoint1 `OCCLUDING_CONTOUR` elements. Reported records must already be uniquely canonical-ordered by `(occluder_surface_id, occluded_surface_id)`; duplicates and noncanonical order reject rather than being normalized. Positives must equal reported endpoint1 pairs **before** visibility/inventory treatment. Both sides must be currently visible lifecycle nodes, not merely remembered inventory members. Unknown/absent sides, incompatible association, malformed ownership, invalid coordinates or conflicting records reject atomically. Opposite directions are permitted; no DAG or transitivity is inferred. Valid local positives may coexist with ambiguous/unresolved elements elsewhere; those elements do not supply positives or negative claims.

The available rules are exactly `oriented_boundary_ownership_complete_v2` and `oriented_boundary_ownership_with_counterfactual_crosscheck_v1`, with their existing meanings preserved. Neither is substituted with a new predicate. Valid unavailable evidence uses the existing `UnavailableOcclusionAnnotation`, carries neither endpoint elements nor reported positives nor an available rule, and advances time. Mixed availability is unresolved. Available empty support also advances time and means only no positive sampled contour support supplied; physical non-occlusion remains UNKNOWN.

Memory stores each observed directed pair and its latest positive support index. Current-supported means latest support equals the accepted relation observation index. All older pairs are stale history, including after unavailable/empty evidence; they cannot assert continued occlusion, cause of absence, destruction or future reveal. No new lifecycle nodes are created or hidden catalogue retained.

`feature_bytes()` contains only version, observation index, availability and pair/support records. Binding and rule provenance remain outside these features in the separate reference's canonical serialization. Canonical bytes reuse `canonical_json_bytes`: sorted object keys, compact separators, UTF-8, unescaped Unicode, finite JSON numbers, no BOM/newline. Pair records sort uniquely by `(owner, affected)`; decode validates closed keys, types, token/time invariants, availability/rule consistency and exact decode/re-encode spelling (including duplicate-key rejection). Bindings require external validation against the accepted lifecycle before actual use; decode/re-encode is not qualification. Full serialized storage charges all retained pair and binding/rule metadata. `storage()` also reports feature bytes and pair counts; interpreter RSS, transaction copies, original lifecycle and retained snapshots must be charged separately. There is no compactness or resource-performance claim.

Independent public test expectations select owner/other-side from original endpoint records using owner-side declarations, without the production aggregation. Tests cover positive/unknown/stale, both rules, unavailable versus empty, contradictions before visibility treatment, chronology/pre-fetch permissions, ambiguous coexistence, opposite directions, renaming and canonical round-trip. The guarded checker denies native/model/producer imports and prints a deterministic synthetic serialization/projection inspection. These are software checks, not independent physical samples.
